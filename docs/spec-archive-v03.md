# SPEC-ARCHIVE V0.3 功能对齐

功能与页面基准：`SPEC-ARCHIVE-V0.3-Source-20260806.zip` 中的 HTML、JavaScript 和 `server-lan.js`。

| 原版功能 | 当前实现 |
| --- | --- |
| 文档库：手册 / BOM 切换、分组、关键词搜索 | 保留原版页面交互；多关键词同时匹配，支持原版中文技术词翻译 |
| 手册分类 / 厂商筛选 | 根据当前库动态生成选项 |
| BOM 所有板型 / 所有主芯片 / 其他 | 保留 RD、PD 文件名识别规则，增加 DB · 验证板，识别对应主芯片和板名 |
| 时间排序 | 默认最新在前，可切换最早在前；器件手册按上传时间，BOM 按文件修改时间（缺失时用上传时间）；跨分类按时间排列 |
| 上传手册 | 多文件、拖拽、文件名推断、正文提取、AI 元数据、进度、逐文件确认 |
| 上传 BOM | XLS / XLSX，文件修改时间排序，自动识别板型、主芯片、板卡名称 |
| 管理 | 原管理员账号登录、编辑、删除、退出、重建全文索引 |
| 预览 / 下载 | PDF、图片内嵌预览；BOM 多工作表预览，每表最多 200 行 / 40 列；保留下载原件 |
| AI 助手 | 原版 Responses 接口、文档相关度、正文上下文、中文答案、资料来源和模型名称 |

页面与原版保持相同结构，颜色与平台保持一致，补充手机适配、已有资料重新提取入口、失败文件重试和异步提取时的手工输入保护。

## 平台适配

- 原版页面通过 `/apps/excel-material-search/api/v03` 接入 Flask；继续使用原有 PostgreSQL `archive` 数据区域、文件目录和管理员账号，不迁移到 JSON 元数据。
- 原版的浏览、检索、预览、下载、AI 问答对普通用户开放；写操作及元数据分析需要管理员身份。原有 API 保留兼容性。
- 原版上传的 Word `.doc` 与图片可以保存和下载；正文索引支持 PDF、DOCX、XLS、XLSX、TXT、Markdown。扫描 PDF 无可提取文字时需要手动填写，未引入 OCR。
- 文件名推断、AI 提取均供管理员确认。现有空白分类不自动改写；可在编辑资料时点击“从正文提取信息”，确认后保存。
- 上传同内容文件沿用现有去重机制，保留原文件 ID。正文索引清洗无效 Unicode，原文件字节不变。
- 未复制原版静态暴露服务目录和认证配置的实现。管理员认证使用现有账号和会话验证。

## AI 配置

在平台受限运行配置中提供 `SPEC_ARCHIVE_AI_API_KEY`、`SPEC_ARCHIVE_AI_BASE_URL` 和 `SPEC_ARCHIVE_AI_MODEL`。应用使用专用 AI Key，凭据不进入源码、构建上下文或页面。

## 验证

- 后端隔离测试覆盖访客/管理员权限、完整文件流程、筛选、XLS、异常 PDF、AI 正文上下文、无配置和上游失败。
- 前端测试覆盖登录、筛选、预览、提取后确认、手工修改保护、AI 引用和失败重试。
- Docker 构建执行后端和前端测试及生产打包。
